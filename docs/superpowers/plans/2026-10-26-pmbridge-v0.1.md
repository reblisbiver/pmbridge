# PMBridge V0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a reusable macOS PMBridge CLI that bootstraps project configs, supervises durable Codex jobs, recovers them, checks health, and returns status to a ChatGPT Web conversation.

**Architecture:** Python stdlib-only package with a stable JSON CLI contract. Runtime state lives under `~/.pmbridge`; Codex execution is owned by a watcher process; Edge callback and launchd are adapters around a small durable state machine.

**Tech Stack:** Python 3 stdlib, unittest, zsh/osascript, launchd, Git.

**Spec:** `docs/spec.md`

## Global Constraints
- No third-party Python dependencies in V0.1.
- macOS + Edge only.
- Bootstrap must never initialize Git without explicit `--init-repo`.
- GitHub remote creation is a separate explicit action, not automatic bootstrap behavior.
- Existing project-specific bridges are not migrated or modified by PMBridge.

## Review Focus
- Non-Git path must return `NEEDS_REPO_CONFIRMATION` without side effects.
- Terminal job states must not regress under concurrent recovery/watcher activity.
- Duplicate watcher/notification races must be idempotent.
- User composer content must not be overwritten by callback transport.
- Missing Codex/Edge/ChatGPT tab must produce actionable doctor output rather than false READY.
